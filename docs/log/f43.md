# F43 — a print-mode recipe names its approval mode

Envelope F43, correction 1. Base `cafac16`. Holds: this file and `factory/tools/seat.mjs`.

## What the lane found

Sitting 11 launched two seats from the `qwen-code` recipe exactly as written. Both read
their packet, did the analysis, wrote nothing, and said so only because they thought to.
The carrier line was `qwen --auth-type openai --model <id> -p -` — print mode, so no
terminal, while `--approval-mode` defaults to `default`, which the help spells as "Require
approval for file edits or shell commands". Every edit and every command waited on an
approval nobody was there to give. The recipe named the right harness and the wrong mode,
and nothing in the file could say so (T07).

## Correction 1 — the scope is print mode, not the stdin carrier

The first return keyed the approval rule on a recipe rendering a stdin carrier, and named
`goose` as a gap in its own log: `goose` renders none, so the rule could not read it, and
deleting goose's note left `--self-test` green. The dictated mutation did not fire on one of
the three objects item 2 named, and the comment stated the false premise as a fact (D-62).

The rule now scopes on print mode. A recipe is a print-mode launch when its own rendered text
says so — tested with the note stripped out, so the marker stands on the recipe's own words
and deleting the note cannot also delete the recipe from the rule — or when it hands the
packet to a harness on stdin, which is that same launch by another route. The false sentence
is gone.

The wider scope pulled in `deepseek-openai` and `claude-code`: each declares print mode and
carried neither a mode nor the note, so each now carries the note. `pc-dashscope` and
`cloud-dashscope` stay in scope through their carrier, so deleting the mode from their qwen
line still reds — a marker that dropped them would re-dig the same hole one recipe over.

## The scope's edges

Read off the shipped rule, not off a reading of the recipes: a copy of the file with the
nine note sites emptied and every carrier option removed fails `--self-test` naming the
in-scope set — `qwen-code aider opencode goose deepseek-openai claude-code local-hands
cloud-grok cloud-git-bus pc-token pc-dashscope cloud-dashscope desktop-qwen desktop-deepseek`,
14 of the 19 ids `list` prints.

The five it excludes — `git-bus`, `codespace`, `cursor-desktop`, `help-fork`, `help-collab` —
render no launch of a seat at all: a pointer to the recipe that does launch, or an advisory.
There is no mode for them to state, and the exclusion is right for the text they carry today.

A recipe added later enters by the same two routes: a seat launch says print-mode in its own
words or hands a packet over on stdin. The residual gap is named rather than smoothed over —
a new seat recipe that writes neither would default out, and the honest fix for that is a
launch-detecting marker, which needs the allowlist for pointer recipes that this factory has
not built.
