## Self-check, and what it changed

1. The header sentence about the unguarded import said it ran the check against "the importing
   script's root". It runs against the kit root this file derives from its own location.
   Corrected: a false sentence in the diff is a blocking defect.
2. P2 gained the negative half — the clause-for wording must NOT print on a clause-free page —
   because property 2 is the one that says the two answers stay distinguishable, and `wants`
   alone proves only one of them.
3. P8 runs a real CHILD process rather than a dynamic import inside the suite. In-process, the
   guard-removed mutation makes the imported module call `process.exit(0)`: the suite would
   exit 0 with no FAIL line and the gate would read a false green. The statement the importer
   runs after the import IS the assertion, so a child that dies first cannot pass.
4. The `spawnSync` binding sits below MARKER, because the "check path runs no program" clause
   scans exactly the region above it and ESM hoists a top-level import whatever its position.
   P6c stays green and keeps its meaning.

Every fixture that expects no error still asserts a positive fact: the examined count, the
verdict text, and — P8, P9 — the sentinel the child prints, or the ok line and exit 0 on the
clean root. A fixture cannot pass by not running.
