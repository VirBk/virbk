# F31: the packet prefix is byte-stable, and a check proves it

## What changed

`factory/tools/packet.mjs`, inside `selfTest()` only. `seatPacket`, `cpPacket`, `render`,
`boardSlice` and `trapsDigest` are untouched, so the bytes the packet prints are what they were.
Two assertions:

- the last part `seatPacket` returns is named `envelope …`, so the envelope cannot drift to the
  front of the reading path;
- the rendered bytes *before* that part are byte-identical for two different lane ids — the first
  envelope this board has issued, and an unissued lane whose part is the `MISSING` sentence.

The lane id is read from `envelopes(root)`, not hard-coded, so the assertion still bites on a
board with nothing issued (`F-none-issued` is then the lane, still a `MISSING` part, still last).
The comparison renders `parts.slice(0, -1)`; comparing whole renders always differs, because the
envelope differs between lanes by definition. Nothing here asserts cross-sitting stability: the
board slice carries `now`, and the traps digest moves when a trap is absorbed.

Why: the packet orders AGENTS, BOARD slice, traps digest before the envelope so a provider prefix
cache hits the front (T45), and the file says so in a comment. Nothing failed if that order
changed. Landing step 16 ran this self-test for size, ledger leaks and `MISSING` only. T61.

## Negative proof

`seatPacket` was temporarily reordered to put the envelope part first — one added line,
`parts.unshift(parts.pop())`, immediately before `return parts` — and the self-test run:

```
$ node factory/tools/packet.mjs --self-test
packet self-test failed
  the seat packet does not end with the envelope part: traps digest is last
  the bytes before the envelope part differ between two lane ids
```

Exit code 1; both named messages fire. The line was then removed. The returned diff is 16 added
lines and no reorder:

```
$ git diff -- factory/tools/packet.mjs | grep -c unshift
0
```

## Self-check

- `node factory/tools/kitCheck.mjs --self-test` fails on two **live** rows. Both are present at the
  issuance base; this was shown by stashing this lane's only edited file and running the same
  command:

  ```
  $ git stash push -q -m f31-noise factory/tools/packet.mjs
  $ node factory/tools/kitCheck.mjs --self-test
  kitCheck self-test failed
    live: B factory/packages.json has no row for board lane F31
    live: C lane F31 holds docs/log/f31.md, which is not in the tree
  $ git stash pop -q
  ```

- B is not this lane's to fix. `factory/packages.json` carries F0–F30 and no F31 row; the board
  carries lane F31 issued. The issuance commit added the lane without the row, and
  `factory/packages.json` is not in this lane's holds — adding it would be a stray file. The
  control plane owes the row, and landing step 14 runs this same check, so the gate will hold the
  landing until it is there.
- C is this lane's own record: `docs/log/f31.md` is the file C asks for, and it is in the tree
  from this commit.
- A test that cannot fail was the risk here, so the negative proof above is the check: the two
  assertions are silent on this tree and loud on the reordered one. `seatPacket(root, null)` has
  no envelope part at all, so the assertions run on lane ids that produce one; the `null` path is
  untouched and its `MISSING`/size assertions still run.
- No claim here is about cache hit rate, token savings or cost. Nothing pasted above came from a
  meter.
- Not measured: an end-to-end `node factory/tools/landingGate.mjs` run on an archive of this
  commit. Landing step 14 will be red on B until the control plane adds the row, and that is a
  property of the issuance commit, not of this diff.
