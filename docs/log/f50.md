# F50 — the entry-point fixture runs where the gate runs

## What changed

`factory/tools/landingGate.mjs` only.

- `fixtureDirs().done()` no longer swallows a failed removal: it calls
  `removeTree()`, which retries, REPORTS a removal it cannot finish and
  returns the reason. A throw there would hide the finding the fixture was
  reporting (T79). `rm` and `report` are injectable so a fixture can drive
  that path without waiting for the platform.
- `makeTempRepo()` lays out a throwaway git repository under the OS temp
  dir holding a copy of this tool and `experiment.mjs`, then `git init`,
  one commit, `rev-parse HEAD`. It never throws: a repository it cannot
  make comes back as an `error` string. `spawn` is injectable.
- `fixture7` no longer returns early when there is no repository — that
  early return was S24's hole. It builds its own, spawns the copy inside
  it as the process a person runs, and asserts on that. A repository that
  cannot be created is a FAILED fixture naming why; it never skips.
- `fixture10` (property 4) and `fixture11` (property 5's report clause).

In this file `[N …]` is the FIXTURE number, so the new assertions are
tagged `[7 own copy]`, `[7 cleanup]`, `[10 repo failure]`, `[11 cleanup]`.

## Self-check

Driven against a reviewer's list. What it changed:

- The wiring mutations were first run in a "fake repo" holding only the
  two tool files, where the self-test's own archive checks red as well
  (`archive missing factory/landing-checks.json`), so one property looked
  like several. Re-run from the real checkout, each reds its own lines
  only.
- The new tags were first `[4 repo failure]`, `[5 cleanup]`,
  `[6 own input]`, which collide with fixtures 4, 5 and 6 in a file where
  the number is the fixture. Renumbered to `[10 repo failure]`,

  failure is an `error` and `fixture7` FAILS on it. Property 4's mutation
  is the proof it cannot pass quietly.

## Correction 1 — fixture7's own branch, not the helper

The defect: `fixture10` proved `makeTempRepo` populates `error`, but
`fixture7` called it with no injected failure, so on every ordinary run
`repo.error` was empty and fixture7's OWN early-return branch — the
`errors.push` that reports a repository it could not make — never
executed. A second fixture on the helper would have changed nothing.

- `fixture7(errors, opts)` now passes `opts` through to `makeTempRepo`,
  so a refusing `spawn` can be injected into the path fixture7 takes.
- New `fixture12` drives fixture7's CONSUMPTION with a refusing spawn on
  its own errors array, and asserts the report exists and names the
  reason (`git init` plus the stderr the refusing git wrote). It needs
  no absent git, so it runs where the gate and the Action both run.

    $ cd /tmp/f50-corr1/bare && node factory/tools/landingGate.mjs --self-test

## Self-check, correction 1

The self-check asks the new fixture whether it could have failed; the
mutation above is the proof. It also caught the first mutation attempt:
deleting every line matching the branch's message also removed fixture12's
own `startsWith` predicate, which crashed with `ReferenceError: line is
not defined` instead of a clean red. The mutation was narrowed to the
`errors.push(` line, and then reds `[12 f7 consumption]` alone. New tag
`[12 f7 consumption]` verified unique against the other `[N …]` tags.
