# F46 — the packet band names the context that reaches a writer

## What changed

`factory/tools/sizeBudget.mjs` only.

- The shared band is relabelled `packet prefix (shared, no envelope)`. It still measures
  `total(seatPacket(root, null))` and still caps against `context.seatPacketKb`.
- A second report, `seatTotals(root)`, prints one row per file in `factory/envelopes/`:
  `total(seatPacket(root, lane))` against `seatPacketKb + envelopeKb`, both read from
  `factory/budgets.json` — never hardcoded. Its label is
  `seat total <LANE> (prefix + envelope)`: what a seat of that lane receives.
- A lane row is a budget, not a schedule, so the 80% band never applies to one.
- No envelope issued: the report prints
  `no envelope issued — nothing to measure; the prefix above is what every seat receives between landings`
  and the step passes. It cannot fail for having nothing to measure (T09).

## The measuring command

- `node factory/tools/sizeBudget.mjs` → rc 0; prefix `BAND 99.8% 25.9 / 26.0 KB`;
  `99.7% 31.9 / 32.0 KB seat total F46 (prefix + envelope)`;
  `99.5% 31.8 / 32.0 KB seat total F50 (prefix + envelope)`.
- `node factory/tools/packet.mjs seat F46` → `31.9 KB`; `seat F50` → `31.8 KB`.

The agreement is the property, not the formatting: `seatTotals` derives each row by
calling the same `seatPacket(root, lane)` the meter does, so the number a control plane
reads before issuing is the number that reaches the writer.

## The prefix, before and after

- HEAD (`git show HEAD:factory/tools/sizeBudget.mjs`): `BAND 99.8% 25.9 / 26.0 KB  seat packet`
- tree: `BAND 99.8% 25.9 / 26.0 KB  packet prefix (shared, no envelope)`

25.9 KB both. Byte count, cap and verdict unchanged; only the label moved.

## Six properties, one mutation each

`node factory/tools/sizeBudget.mjs --self-test` reds the named property and no other.
Harness `%TEMP%\f46-mutate.mjs`, outside the repo; sha256[:16] in `31019c074c0ff89a`,
out `31019c074c0ff89a`. Every mutation exits 1.

1. P1 — the lane total equals what `packet.mjs seat <LANE>` prints, both sides derived
   in the fixture. Mutation: row bytes = `sizeOf(<envelope file>)`.
   `P1: the report says 1.2 KB for F00, packet.mjs seat F00 says 1.6 KB`
2. P2 — no envelope → the report says so and exits 0, and the fixture can fail.
   Mutation: delete the sentence's `else` branch.
   `P2: a tree with no envelope did not say so: <report>`
3. P3 — a total over the combined cap fails and names the lane, and only the offending
   lane with several envelopes present. Mutation: print `overText(r)` for every row.
   `P3: the failure named a lane that is under its cap: seat totals failed: … 0.6 KB > 32 KB`
4. P4 — prefix row unchanged in object, cap and verdict; fails over its cap.
   Mutation: prefix bytes + 4096.
   `the prefix row does not measure the prefix` / `P4: the prefix row says 4.4 KB, the prefix is 0.4 KB`
5. P5 — both caps read from `factory/budgets.json`; the verdict moves when either moves.
   Mutation: cap = `seatPacketKb + 6`, envelopeKb ignored.
   `P5: a total over the combined cap was not failed: …` / `P5: the cap printed is not seatPacketKb + envelopeKb from the file: 59.7% 4.4 / 7.4 KB`
6. P6 — the label no longer calls the prefix the seat packet; the total is labelled as
   what a seat receives. Mutation: prefix label back to `seat packet`.
   `P6: the shared band is not labelled the prefix: … seat packet` / `P6: prefix is still called the seat packet: … seat packet`

Two notes. P1's fixture derives the lane total from `total(seatPacket(d, lane))` rather
than reading the report's prefix row, or M-P4 would red it too. P3 deliberately mutates
the "only the offending lane" half instead of emptying the failure list, because P5
reads the lane verdict out of that block — emptying it would red P3 and P5 together, and
a mutation that reds two properties is the wrong mutation.
