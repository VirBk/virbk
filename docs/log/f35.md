# F35 — the scan opens the child's TRAPS file and turns its rows into intakes

Changed set: `factory/tools/alumni.mjs`, `docs/log/f35.md`. `contracts/intake.v1.json`
is held but needed no change — the reason is under item 3.

## Item 1 — the scan reads the rows of the file it already listed

`scan()` already named `TRAPS.md|yaml|yml` in its `files` list and never opened
one. Added: `parseTrapsYaml` (block-list subset — `- id:` plus indented
`key: value`, a wrapped continuation appended to its key), `parseTrapsMarkdown`
(col-0 bullets and ATX headings, body to the next row), `trapsReport(root, child,
at)`, `splitCheck`, `mintId`, `trapsCandidate`, `titleOf`, `collapse`, `floors`.
`scan()` now returns `traps` beside the size signals, and `printScan` prints the
table and the counts.

    $ node factory/tools/alumni.mjs scan <C:/Users/acces/AppData/Local/Temp/f35-drive/tree> otto
    TRAPS rows    file                rows  with a check  without
                  docs/TRAPS.md       75    19            56
                  factory/TRAPS.yaml  75    19            56
                  ops/TRAPS.md        1     0             1
    rows 151, with a check 38, without a check 113
    emit 38 candidate intake(s)

## Item 2 — the two cases are split and never blurred

One function, `splitCheck`, decides "names a check" for both formats. A row that
names one becomes a candidate; a row that names none is counted, held with a
reason (`names no check`, `check under <n>`, `rule under <n>`, `row id repeated
in this file`) and reported by id — printed by `printScan` and returned in
`report.files[].held`. The counts above are those two cases: 38 named, 113
without. An emitted candidate always carries a non-empty check; a candidate with
an empty check would be refused by the gate after the owner had read it, which is
worse than a row that was never emitted.

## Item 3 — every emitted candidate validates, with no hand-editing

    $ node factory/tools/intake.mjs <an emitted candidate>
    intake ok  C-OTTO-T49

Provenance rides in fields the contract already carries: `title` is
`<rowid> <rel> — <title>` and `charged` is `Charged in <child> at <rel> row
<rowid>: <rule>`, so the row can be found again in that child's file.
`contracts/intake.v1.json` is untouched on purpose: it sets
`additionalProperties: false` and `factory/tools/intake.mjs` keeps a hard-coded
key list that reports `unknown fields`, so a new `source` field would mint
candidates the gate refuses — a made-up field is worse than no field. `at` is
required by the contract, so `trapsReport` takes `at` and threads it down
(default: today, UTC).

## Item 4 — read-only on the scanned tree, and it stays that way

The only new call is `readFileSync` on a path the scan already listed. Measured,
not asserted — the same tree, hashed before and after a `scan` and an `intakes`:

    $ find "$T" -type f | sort | xargs sha1sum | sha1sum
    before 2b2ae7a723481469d49d251826439e7230ecff41 *-
    after  2b2ae7a723481469d49d251826439e7230ecff41 *-
    read-only on the scanned tree: byte-identical

The self-test also snapshots a fixture tree (relpath + size + sha1 prefix) before
and after, and proves the snapshot detects a deliberate write while the write is
present.

## Notes for the next seat

- `alumni.mjs` is a CLI with no entry guard: importing it runs its CLI and exits
  the importer, which is how the first drive tree failed to build. Spawn it,
  never import it. The readers are exported for the lane that adds the guard.
- A prose bullet that opens with an id-shaped token is counted as a row and held
  by id. That is deliberate: reported, not emitted, not silently dropped.
- Emitted real rows are not driven through `intake.mjs` as a set, because real
  trap rules legitimately contain words its refuse list bans.
