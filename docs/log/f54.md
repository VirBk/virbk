## What changed

`factory/tools/seat.mjs`

- The launch NAMES the store. Ten of the nineteen rendered recipes carry the harness's
  non-repository context — seven comment lines ending `#   node factory/tools/seat.mjs store`, from
  `storeStdin()`. The other nine hand over no packet, so their omission is correct:
  goose, deepseek-openai, claude-code, git-bus, codespace, cursor-desktop, help-fork, help-collab,
  desktop-deepseek. None OPENS with it: in `qwen-code` it begins at line 22 (`grep -nF 'Before
  the packet'` prints 22 of its 34 lines). `storeStdin()` is the first element of
  `launchStdin()`, so a recipe rendering its launch through `launchStdin()` always carries the block,
  and the self-test's store rule reds any packet-carrying recipe without it; a recipe calling neither
  `launchStdin()` nor `packet.mjs` hands over no packet and nothing reds — the nine above.
  `~/.qwen/memories` is injected ahead of the packet, in no packet, under no budget and in no gate;
  nothing in this repository could tell a successor it is there.
- New `store [--store <path>]`: the path, the file count, the total bytes and each file with its size,
  read from the store in the same act as the print (T04), never carried (P3). An absent store is a
  named zero, `absent - looked and found none (0 files, 0 bytes)`, and a machine with no home
  directory says so in the path slot (P2). Nothing reads, copies or prints a store file's contents —
  name, size and count only. The report exits 0 in every branch, so a storeless machine still
  launches, and no store is needed to test it.
- P4: the total is reported against the stated baseline `7292 bytes over 5 files` (D-72, 2026-09-22)
  with a signed drift, and the line says `reported, not gated` (T82). Growth is visible; it fails
  nothing.

`factory/tools/seatReturn.mjs`

- New exported `reviewErrors(review, where)`: the reviewer's `tier`, `tokens` and `toolUses`, all three
  required when the object is present, and no field outside the set. A row present but EMPTY is a
  named refusal (P6): a lane nobody reviewed and a review nobody counted must not read the same.
- `returnErrors` accepts the optional `review` and checks it with that one rule; `rowKey` appends its
  three numbers, so one lane at two review costs is two rows; `record()` copies it onto the stored row
  and `storeErrors` checks it with the same rule; `spend` prints `reviewed rows N  reviewer tokens T
  tool uses U`, and only when a row carries one. `schemaErrors` requires the contract's
  `review.required` to equal that one list, so loosening a field to make a disagreement pass is red
  where the landings look.
- P7: the CLI tail sits behind the entry guard packet.mjs, route.mjs, alumni.mjs and envelopeCheck.mjs
  carry — `const isEntry = /seatReturn\.mjs$/.test(process.argv[1] || "")`. An import no longer runs
  the dispatch and exits.

`contracts/seat-return.v1.json` — new optional `review` object (`tier` string, `tokens`/`toolUses`
non-negative numbers, required all three, `additionalProperties: false`), described with D-72 and the
F52 measurement. The top-level `required` is still the same eight.

## Self-check, and what it changed

1. The first no-home fixture spawned a child with USERPROFILE/HOME/HOMEDRIVE/HOMEPATH deleted from the
   env block and the child still reported `C:\Users\acces`: node on Windows re-populates those from
   the OS token whatever env it is handed. No child process can be made home-less here. The fixture is
   now driven in process against the exported `memoryStorePath()`/`storeReport()`, deleting from the
   live `process.env` and restoring it in a `finally` — the only way this machine can be simulated.
2. `packetStdin` renamed `launchStdin` (10 sites): it no longer describes only the packet. The old
   name would have been a false sentence in the diff.
3. Nothing else in the seven drives changed the code. One fixture detail was checked rather than
   fixed: the store line contains `seat.mjs`, so the recipe's `packet.mjs` carrier scan is unaffected.
