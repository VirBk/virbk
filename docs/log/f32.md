# F32 — the control plane reads the meter into the return

Branch `writer/F32`. Seat `pc-dashscope`. The launcher passed the model string
`deepseek-flash` (what the launcher passed, not the topology id — S10). Base `da0d13a`.

## What changed

`factory/tools/seatReturn.mjs` — this adds; it replaces nothing.

- `node factory/tools/seatReturn.mjs meter <project-path>` reads the newest session in
  `$USERPROFILE/.qwen/usage_record.jsonl` (`$HOME` on POSIX) whose `project` equals the
  path given, and prints its `requests`, `inputTokens`, `outputTokens`, `cachedTokens`,
  the session, and the absolute path of the file it read. Read-only: no file written, no
  network, no number computed. Record or matching session absent: one line, exit 1.
  The project is matched exactly — separators fold, case folds only on Windows — and the
  newest session by `timestamp` wins, not the last line of the file.
- A return may carry `tokens: { in, out, cached, requests, source }`. `spendUsd` is then
  optional; without a named `tokens.source` it is still required. A dollar the record
  cannot support would be a durable false measurement.
- The store keeps a metered row with no `spendUsd` key, and `spend` reports such a row as
  `unpriced` instead of summing it as a zero.

`contracts/seat-return.v1.json` — `spendUsd` left `required`; added top-level `anyOf`
[`spendUsd` | `tokens`]; added the `tokens` object. The `runtime` enum is unchanged and
still checked against the live catalog by `--check-contract`.

## What the self-check changed

1. One meter assertion was a no-op — `if (!readMeter(rec, "  ").ok === false)` is false
   either way, so it proved nothing. It is now `if (readMeter(rec, "  ").ok)`, which is
   the blank-project case it names.
2. `spendUsd` now refuses `NaN` and `Infinity`: the old test was `typeof row.spendUsd
   !== "number"`, and `typeof NaN === "number"`. Tightening, not a removal — every
   existing field and assertion still holds, and the schema was already `minimum: 0`.
3. `rowKey` appends the five `tokens` fields only when a `tokens` block exists, so a row
   stored before F32 keeps the key it was written with; `--record` still refuses a row
   already in the store.

## The meter and this lane

`meter 'C:/Users/acces/grok-f32'` printed the specified absent case above. That is the
harness's timing, not a fault of the command: qwen-code appends a session's row to
`usage_record.jsonl` when the session closes (`persistSessionUsage` on `registerCleanup`),
so this seat's own row lands when this print-mode process exits. The control plane runs
the same command after the seat closes and pastes `requests` → `tokens.requests`,
`inputTokens` → `tokens.in`, `outputTokens` → `tokens.out`, `cachedTokens` →
`tokens.cached`, `source` → `qwen usage_record.jsonl`. No number is written here that a
command did not print.

The record holds every project and more than one session per directory (it already holds
two for `grok-f31`), so "newest session" can be a later session that ran in the same
directory; the meter prints the `session` id it read, so which one was read is visible.
