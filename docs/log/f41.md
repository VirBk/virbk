# F41 — A record cites only what resolves, and dates only what UTC has reached (S18)

## What changed

`factory/tools/kitCheck.mjs` gains two checks inside `check(root)`. Gate step 14
(`node factory/tools/kitCheck.mjs --self-test`) already calls `check()` live on the tree
under test, so the two checks enter the gate with no edit to `factory/landing-checks.json`.

- **H — a record cites only a path that resolves.** Scans `docs/log/*.md` for backticked
  path citations: a token that contains `/`, has no whitespace, ends in .mjs/.json/.yaml/
  .yml/.md/.js/.ts, and holds none of `* < > ?`. Every one must exist in the tree under
  test or sit in `CITATION_ALLOW`, an array of `{path, why}` seeded with exactly five
  entries, each with a one-line reason. An allowlist entry whose path resolves is a stale
  exemption and also fails.
- **I — a date field is not ahead of UTC.** Reads the `at` field of every `factory/decisions.json`
  row and every `factory/board.json` ledger row and compares it to
  `new Date().toISOString().slice(0, 10)` read in the same act (T04). Fields only; prose
  is not scanned, so the ledger row narrating the 2026-09-21 mis-dating incident stays green.

each was then restored and the command re-run green.

   Restored; green.

## Self-check — what it found

Drove all four mutations, restored every file, and re-ran. Two things it settled:

- Ledger rows carry no `id` field (keys are `at` and `event`), so a ledger finding is named
  by position, `ledger[<i>]`. A row that ever grows an `id` is named by it instead.
- The fixture's minimal board already contains `factory/board.json`, so the stale-exemption
  probe reds the clean fixture as well as the live tree — visible in mutation 4 above.
