# F38 — a return's model is checked against the meter

Branch `writer/F38`. Seat `pc-dashscope`; the launcher passed `deepseek-v4.1-flash`. Base
`ecf24e8`. Keystone: the "spend pasted in the lane log" step of the dual-runtime loop, made
checkable.

## What changed

`factory/tools/seatReturn.mjs` — `--record` now refuses a return it cannot check.

1. **Recording checks the return's model against the meter (T69).** `--record` requires
   `--project <path>`, reads the meter for it, and requires the return's `model` to agree
   with an id the meter recorded there. Agreement stores that id as `meterModel` beside the
   launcher's claim in `model`; a disagreement refuses and names both. A seat cannot see its
   own model, so claim and measurement sit apart.
2. **No meter is a refusal — not a pass, not a crash.** `readMeter` returning `ok: false`
   refuses, prints the reason and the rows read, stores nothing; an unmeasured model is
   never recorded silently.
3. **Agreement goes through the map that owns the relation (T48, T75).** `providerId()` asks
   `route.mjs`'s `resolve()` for the id a model is served as, and `sameModel()` compares
   those, so both sides are canonicalized and the compare is symmetric. The agreeing pairs
   are `deepseek-flash`/`deepseek-v4.1-flash`, `deepseek-v4-pro`/`deepseek-v4-pro-0813` and
   `qwen3-coder`/`qwen3-coder-plus`; every other id agrees only with itself. The unversioned
   DashScope id is **not** folded: the router never sends `deepseek-v4-pro` to that base, and
   the factory's record shows it from the native base at `grok-f31-rev`, a different price.
   Both ids therefore sit on the row — `model` the claim, `meterModel` the measurement — so a
   price question can see which was served.
4. **The contract gained an optional field.** `contracts/seat-return.v1.json` gained
   `meterModel` (string, minLength 1) as a property only — deliberately not required,
   because a seat cannot know which id answered. `--check-contract` now refuses a contract
   that requires it.
5. **The store's shape is checked where the landing looks.** `storeErrors()` checks
   `factory/returns.json`: the rule string, no repeated key, and per row the required
   fields, no unknown field, a 16-hex key, a parseable `at`, non-empty lane/runtime/model, a
   sha base, and the optional fields' types. It runs in `--self-test` (against the live
   store; gate step 20 runs `--self-test`) and in `--check-contract`, proved on bent copies.

`rowKey` appends `meterModel` only when present, so pre-F38 keys — the F32 row's included —
are untouched and recording twice does not double a row. The F32 row still validates.

## The five mutations

Both halves of the negative proof: a genuine disagreement is refused and a legitimate
agreement is recorded. `wrong.json` (`qwen3.7-flash`) against a meter recording
`deepseek-flash` is refused, both ids named; `return.json` (`deepseek-v4.1-flash`) against
that same row is recorded, `meter says deepseek-flash`. String equality refuses the second
and accepts the first (mutation 3).

1. **A return whose model disagrees** — refused, exit 1, naming both ids (above). With
   `--project` absent it also refuses: `--record needs --project <path>; a model nobody
   measured is not stored`.
2. **A project with no meter row** — refused, exit 1, naming the file and the rows read;
   nothing stored (above).
3. **`sameModel` by raw string equality** (`return String(a) === String(b)`):

       node factory/tools/seatReturn.mjs --self-test
       seatReturn self-test failed                                  exit=1
         the router's map does not fold deepseek-flash and deepseek-v4.1-flash
         the router's map does not fold deepseek-v4-pro and deepseek-v4-pro-0813
         the router's map does not fold qwen3-coder and qwen3-coder-plus
         a return that agrees with the meter was refused: model disagreement: the
         return says deepseek-v4.1-flash, the meter recorded deepseek-flash
         the store holds 0 rows after one return and one re-record

4. **A required field loosened** — dropping `measured` from `required`, then adding
   `meterModel` to it:

       node factory/tools/seatReturn.mjs --check-contract
       seat-return contract failed                                  exit=1
         contracts/seat-return.v1.json does not require measured

       node factory/tools/seatReturn.mjs --check-contract
       seat-return contract failed                                  exit=1
         contracts/seat-return.v1.json requires meterModel — a seat cannot know it

5. **The stored row's shape changed** — renaming the F32 row's `model` to `modelId` in the
   real `factory/returns.json`:

       node factory/tools/seatReturn.mjs --check-contract
       seat-return contract failed                                  exit=1
         factory/returns.json row 1 has no model
         factory/returns.json row 1 has unknown fields: modelId

   Restored with `git checkout -- factory/returns.json`: `git diff --exit-code
   factory/returns.json` prints nothing and the file is absent from this lane's diff. The
   self-test drives the same mutation on a faithful copy of the shipped store, so the red
   does not depend on bending the real file.

## What the self-check changed

1. `sameModel` by raw string equality crashed the self-test with `TypeError: Cannot read
   properties of undefined (reading 'tokens')` — a refusal left no row and the assertion
   read `rows[0].tokens`. Now guarded, so the test reports the refusal, not a crash.
2. Two failure messages were false on a zero-row store ("a refused return was still
   stored"). Rewritten as row counts, true either way.
3. `storeErrors` named a field without saying what was wrong ("row 1 model"). Now sentences
   ("lane is not a lane id"), and the blank-lane branch is asserted — reverting it fails the
   self-test.

This seat's own meter row lands when this print-mode process exits, so the control plane
re-runs `meter` then.
