# F38 — a return's model is checked against the meter

Branch `writer/F38`. Seat `pc-dashscope`; the launcher passed `deepseek-v4.1-flash`. Base
`23282d6`, rebased onto `c43b532`. Keystone: the "spend pasted in the lane log" step of the
dual-runtime loop, made checkable.

## What changed

`factory/tools/seatReturn.mjs` — `--record` refuses a return it cannot check.

1. **The return's model is checked against the meter (T69).** `--record` requires
   `--project <path>` and a meter id equal to the return's `model`; agreement stores
   `meterModel` beside the launcher's claim in `model`, a disagreement refuses naming both — a
   seat cannot see its own model.
2. **No meter is a refusal — not a pass, not a crash.** `readMeter`'s `ok: false` refuses with
   the reason and the rows read, and stores nothing.
3. **Agreement goes through the map that owns the relation (T48, T75).** `sameModel()` compares
   `providerId()`, `route.mjs`'s `resolve()`, so both sides are canonical: `route.mjs`'s
   `providerModelFor` returns the model unchanged unless the path is `dashscope`, and there
   `HOSTED_IDS[model] || model` folds `deepseek-flash`→`deepseek-v4.1-flash`,
   `deepseek-v4-pro`→`deepseek-v4-pro-0813`, `qwen3-coder`→`qwen3-coder-plus`.
4. **The contract gained an optional field.** `meterModel` (string, minLength 1) — never
   required, because a seat cannot know which id answered. `--check-contract` refuses a
   contract that requires it.
5. **The store's shape is checked where the landing looks.** `storeErrors()` checks the
   shipped `factory/returns.json` — required fields, no unknown field, a 16-hex key, a
   parseable `at`, a non-empty lane, a sha base — in `--self-test` (gate step 20) and
   `--check-contract`.
6. **Correction 1, item 1 — the CLI is driven, not just the function (D-59).** The CLI is the
   only production caller of `record()`, so a fixture calling it with a `meterFile` the CLI
   never passes tests the function, not the invocation that ships. The self-test spawns the
   real command — `seatReturn.mjs <file> --record --project <path>` with `SEAT_RETURN_ROOT`
   and `SEAT_USAGE_RECORD` at a temp store and meter — three times: agreement records one row
   carrying the meter's `deepseek-flash`, the same return is refused `already recorded`, a
   disagreement is refused `model disagreement`.
7. **Correction 1, item 3 — all eight required fields are pinned, not two.** `schemaErrors`
   reads `RETURN_REQUIRED` and refuses a contract that dropped one of the eight, and one that
   requires `meterModel`; the self-test bends both on a copy of the shipped contract.

`rowKey` appends `meterModel` only when present, so recording twice does not double a row. The
self-check also closed a `TypeError` when a refusal left no row, two false zero-row messages,
and `storeErrors` wording.

## The seven mutations

1–5 are the original lane's, kept as the command and what it found; 6 and 7 are correction 1.

1. **A return whose model disagrees** — `--record` refused exit 1, both ids named; without
   `--project`: `--record needs --project <path>; a model nobody measured is not stored`.
2. **A project with no meter row** — refused exit 1, naming the file and the rows read; nothing
   stored.
3. **`sameModel` by raw string equality** — `--self-test failed exit=1`: `the router's map
   does not fold deepseek-flash and deepseek-v4.1-flash`; an agreeing return refused `model
   disagreement`; 0 rows stored.
4. **A required field loosened** — `measured` off `required`, then `meterModel` on:
   `--check-contract failed exit=1`, `... does not require measured`, then `... requires
   meterModel — a seat cannot know it`.
5. **The stored row's shape changed** — the real `factory/returns.json` row 1's `model`
   renamed to `modelId`: `--check-contract failed exit=1`, `row 1 has no model`, `... has
   unknown fields: modelId`. Restored with `git checkout`; `git diff --exit-code` prints
   nothing.
6. **Item 1: `record()` bypassed in the CLI block** — the CLI kept printing success
   (`const out = { ok: true, key: "0000000000000000", rows: 0, meterModel: row.model };`)
   without recording:

       node factory/tools/seatReturn.mjs --self-test
       seatReturn self-test failed                                  exit=1
         the CLI recorded 0 rows, expected 1
         the CLI recorded the same return twice
         the CLI's re-record changed the row count: 0
         the CLI recorded a return whose model disagrees with the meter
         the CLI's refusal changed the row count: 0

   Restored byte for byte; the CLI block is unchanged in this lane's diff.
7. **Item 3: each of the eight required fields dropped in turn** — `required` minus one field
   in the shipped contract, one run per field:

       drop runtime  exit=1  contracts/seat-return.v1.json does not require runtime
       drop model    exit=1  contracts/seat-return.v1.json does not require model
       drop base     exit=1  contracts/seat-return.v1.json does not require base
       drop branch   exit=1  contracts/seat-return.v1.json does not require branch
       drop changed  exit=1  contracts/seat-return.v1.json does not require changed
       drop verify   exit=1  contracts/seat-return.v1.json does not require verify
       drop measured exit=1  contracts/seat-return.v1.json does not require measured

   Gate step 20 is `--self-test`, whose copy of this check goes red the same way — exit=1 per
   field, `a faithful copy of the contract failed: ... does not require <field>`. Restored
   byte for byte; the in-tree contract is unchanged.
