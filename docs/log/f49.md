## What changed

`factory/templates/ENVELOPE.md`

- A `Correction` section, carried ONLY by an envelope whose first line reads
  `ENVELOPE: <LANE> — CORRECTION <n> — ...`. It holds the authorisation the rebase T81 forces:

`factory/tools/envelopeCheck.mjs` (new)

- Reads `factory/envelopes/*.md` as text. The file list is `envelopes()` from `packet.mjs`, so
  "an envelope file" keeps one definition in this kit. Calls no git and needs no repository: the
  landing gate runs it from an unpacked archive. The check path runs no program.
- Refuses, in any envelope of either kind: a force on main, and a force that names no branch.
- Refuses, in a correction: no force-with-lease authorisation for its own lane; an authorisation
  naming another lane's branch; or a clause with no sentence saying main is never forced.
- `--self-test` drives ten clauses over six properties; the live run prints the file set and a
  verdict per envelope, then the errors.

`factory/landing-checks.json` — a 22nd step, `Corrected envelopes authorise their own force`.

## Which matching I chose

Structural, not verbatim. The authorisation is a `git push` line carrying a force flag whose
resolved DESTINATION ref is the branch — flags anywhere in the argument list, the first non-flag
argument the remote, refspecs split at the last colon, `refs/heads/` stripped. The word "force"
anywhere on the page satisfies nothing. The main sentence must put `main`, a `forc` stem and a
negation in ONE sentence. So rewording the template's prose does not break the rule, and a lane
that rephrases its authorisation still passes. The correction marker is the word in the TITLE
position of line 1, because F49's own first line reads "A correction envelope authorises the
force its own rebase forces" and a loose reading would demand the clause of the envelope that
defines it.

## Self-check, and what it changed

Drove the list a reviewer of this lane would be given. It changed four things.

1. Two fixtures asserted another property's output. P2b and P5 asserted the lane's verdict line,
   so the property-1 mutation red three clauses and proved nothing. The assertions were removed
   and every fixture now carries its own error count.
2. P5b was an ordinary envelope, so the property-4 mutation red it. It is now a correction
   carrying a valid own clause plus a bare `git push --force`, which no marker mutation touches.
3. The "runs no program" clause matched `RegExp.prototype.exec` in two regex calls of the check
   path. The token list names only the spawn APIs now.
4. The empty-directory clause pointed at a bare temp root, which is the ABSENT case, so it met
   "no such directory". It now builds an existing, empty `factory/envelopes`.

Empty, absent, and never examined are three answers: an absent directory is one named error, an
empty one is a pass printing `0 envelope(s) examined` and `0 correction(s)`, and a fixture that
expects no error asserts its error count and its verdict text, so it cannot pass by examining
nothing. That is what the empty-directory fixture would catch.
