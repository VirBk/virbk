# F47 — the gate names a shell that cannot run it (S24)

## What changed

`factory/tools/landingGate.mjs` only.

- Before the first step, the shell is probed in a step's own form: a file
  in the log dir, spawned as `bash -e <file>`, cwd set to the unpacked
  archive. A probe shaped `bash -c true` is not this, and does not close
  S24.
- When that shell cannot run the steps, the gate prints ONE diagnostic
  naming the shell, the probe file, the cwd, the commit, the exit or
  spawn error and what the shell wrote to stderr, prints no step line,
  runs no step, and exits 2.
- `EXIT_UNRUNNABLE` is 2; `EXIT_FAILED` is 1. A caller and a seat can
  tell "this shell cannot run the gate" from "your commit is bad".
- The step loop is now `runSteps()`, the verdict is `verdict()`:
  unchanged spawn form, unchanged exit capture, same archive, same lines.
- `--self-test` gained nine fixtures, labelled `[1 ordinary]` … `[9 default]`.

## Self-check

Driven against a reviewer's list. What it changed:

- Fixture 5 first left the self-test throwing `EBUSY` when the real
  launcher held the fixture cwd: `done()` now retries and never throws a
  temp-dir cleanup into the report.
- Fixture 4 first read the diagnostic through the gate's decision, so the
  property-3 mutation moved it too and two properties were red by one
  mutation. It now calls the formatter directly; the decision is fixture
  3's business and nothing else's.
- Fixture 3's stand fails `-e` and `-c` both, on purpose: a stand that
  answered `-c` would be red by the property-5 mutation as well.
- Fixture 1 uses the real shell and 21 real step scripts, and asserts the
  passed verdict — the ordinary case every launch takes, which F45 left
  uncovered. It reds under M1, so it could have failed.

## Correction 1

wiring and the diagnostic's spawn branch were uncovered.
