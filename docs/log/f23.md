# F23

Landing gate runs where the control plane sits.

Changed: `factory/tools/landingGate.mjs`. The archive step no longer shells out to `tar` through
`bash -lc`; it reads `git archive --format=tar` on stdout and unpacks it in process. The archive
is taken with `-c core.autocrlf=false -c core.eol=lf`, so the bytes a size budget measures here
are the bytes the Ubuntu runner measures. New `--self-test` unpacks a tar this file wrote, and,
when a repository is present, compares unpacked bytes against `git show` and the name list against
`git ls-tree`.

Measured, before:

```
$ node factory/tools/landingGate.mjs
archive failed

$ (the underlying failure)
tar: C\:\\Users\acces\\AppData\\Local\\Temp\\gate-a3IyjU: Cannot open: No such file or directory
tar: Error is not recoverable: exiting now
```

After:

```
$ node factory/tools/landingGate.mjs --self-test
landingGate self-test ok

$ node factory/tools/landingGate.mjs
grok landing gate
  steps    13
  ...
GATE PASSED
```

That was the first time the gate ran on the machine the control plane sits at. Until then the only
green gate was the badge from the runner, which is the thing T37 already warns about.

Self-check changed: the first self-test compared archive bytes against `git show` and failed on
every file. The cause was the archive applying the checkout newline conversion, not the unpacker.
Pinning the conversion fixed both the test and the platform drift in the size budgets.

Trap T60. Decision D-40.
