# F48 — a citation check tells a rev spec, a URL and a tree path apart

Envelope F48 (S25). Base `d4427d7`; this worktree was cut at the live main of issuance, `1251bbe`,
branch `writer/F48`. Holds: this file and `factory/tools/kitCheck.mjs`.

## What changed

Rule H's extractor returns each citation with its KIND. A token with no colon is a plain tree path.
A token holding a colon is split at its FIRST colon: a remainder opening with two slashes is a URL
and is not a citation at all; otherwise the left side is a revision spec and the right side is the
path checked against the tree. A failing rev spec is reported as its path part, never as the whole
token. No git call: the gate unpacks an archive, where `files()` already falls back to a walk.

The defect, measured at the objects before the change: over a doc holding
`HEAD:factory/tools/packet.mjs`, the shipped regex returned the whole token, so rule H red a
citation that resolves. F45 paid for it — `8d14688` there rewrote that true citation into
`git rev-parse HEAD:factory/tools/packet.mjs` to get past the check. A backticked URL ending in a
source extension was extracted the same way, while `factory/CONTROL_PLANE.md` section 2 tells the
control plane to record a URL.

## Self-check, and what it changed

Driven as the reviewer's list. Two findings, both closed.

1. The extractor's record — the kind and the whole token it classified — was read by no line. The
   self-test now asserts it directly, over three tokens at once; that assertion is M4's first line.
2. P1's mutation had to be scoped, and the reason is worth writing down: the whole-token mutation
   that S25 shipped reds H1, H2 and H3 together, because all three read the rev branch, so it
   proves nothing about P1 alone. M1 changes only the path a rev spec resolves, which leaves H2's
   verdict (it already fails) and H3's path untouched, and moves H1 alone. A reviewer should read
   P1 and P3 together: both are a rev spec whose path part resolves, and the difference between
   them is only the slash in the rev.

## Not taken

A Windows drive-letter token keeps the verdict it has today, which is red. Over a token such as
C:/Users/acces/x.md the old rule checked the whole token and the new rule checks its path part,
/Users/acces/x.md; neither resolves, and the two `join(root, ...)` forms printed
C:\r\C:\Users\x\y.md and C:\r\Users\x\y.md. No record cites one today, so the live check does not
move.

No cache or token number is written here: the harness meter is appended on session exit, so that
read is the control plane's work, not the seat's.
