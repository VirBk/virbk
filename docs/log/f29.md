# F29: spend and cache hits survive as rows

## What changed

`factory/tools/seatReturn.mjs` gained a `--record` / `spend` pair and `factory/returns.json`.
A return that passes validation can be appended to the store; a return that fails it never
reaches the store, because the check runs first. `spend` sums by lane and by model.

The row is keyed by its own content — lane, runtime, model, base, branch, changed, verify,
measured, spendUsd, cachedTokens — and the key is checked read-first, so an at-least-once
record does not double the spend. The store keeps rows; the lane log keeps the prose.

No new landing step: `seatReturn.mjs --self-test` is already gate step 19, and the store has
no reader the kit does not name there. No cap and no threshold: the store gains about one row
per landed return, and the spend cap stays the envelope's. T65. D-47.

## Self-check

Drove the reviewer list for this lane. Three things it found:

- Validation had to run before the append, or a bad return would be counted. It does; the
  `--record` branch sits after the `fail` on `returnErrors`.
- A timestamp in a stored row is a clock, which T45 forbids in a cached prefix. This file is
  not in the packet and no seat reads it, so the clock is safe here. `at` is UTC.
- An empty store must print, not throw. `spend` on a store with no file says so.

Written by the control plane, not a writer seat, on the owner word. D-45 said the next code
lane returns to a seat plus a fresh reviewer; that is still owed and is not this lane.
