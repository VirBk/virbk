# F44 — the census counts seats, not the processes one launch spawns

## What changed

`factory/tools/seat.mjs` only.

- The lister row shape is now pid, **parent pid**, command line (`SEAT_ROW`), so the
  platform listers report a parent: win32 selects `ParentProcessId` in the same
  `Get-CimInstance Win32_Process` call, other platforms use `ps -eo pid=,ppid=,args=`.
  The lister stays injected — every fixture drives it through `--lister` — and census
  still reads no file.
- The census folds by walking ancestors: a counted row is a seat only when no other
  counted row is above it on its parent chain. The rendered output names one row per seat
  and says how many processes it folded.
- Two fixtures assert the count and the folding, one property per item, and the existing
  T77 fixture keeps its assertions unchanged (it gained a ppid column).

Why the walk and not the immediate parent: measured on this machine a qwen launch is
`cli-entry.js` (counted) → `node --expose-gc .../cli.js` (not counted: the program run is
`--expose-gc`) → another such child → `OpenConsole.exe`, whose path segment
`@qwen-code\qwen-code\...` is counted by the program-position rule. Folding on the
immediate parent leaves 3 rows for that launch; folding on the nearest counted ancestor
leaves 1, which is what the census is for. T77's limit is unchanged and still named: a
process whose program merely lives in a harness install directory still counts, so that
conpty helper is a row — folded, not hidden.

## The mutations

Each was driven by hand at the census block, then the file was restored from a byte copy;
`git hash-object factory/tools/seat.mjs` printed
`bc5eda38d048dc6d110def3cbf6daec1e715d571` before and after each one.

**A — the fold removed, so every matching row counts.** Reproduced by replacing the fold
loop with `const seats = rows;`. It reds item 1's property, and item 2's fixture still
passes:
