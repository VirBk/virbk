## What changed

`factory/tools/route.mjs`

- `droppedIds()` reads `factory/writer-paths.json` dropped.ids. Nothing keeps a copy of it.
  `droppedAudit()` answers `empty`, `dirty` or `clean` and reports how many ids it examined; an
  empty list is a named failure, never a pass (F49).
- `familyOf()` answers `deepseek` for an id the catalog or the hosted map knows, `null` otherwise.
  `resolve()` refuses a null family: `reason unrecognised-id`, with `providerModel`, `path`, `key`
  and `base` all null, and the CLI exits non-zero (D-71). The "not deepseek therefore qwen" prefix
  fallthrough is gone, and the `qwen3-coder` row is out of `HOSTED_IDS`.
- `--self-test` drives the properties through a seam handed its own fixture lists — including the
  empty one, and an id that is a prefix of a live one — and through spawned fixture trees: one
  whose own dropped.ids is empty must fail naming that it examined nothing, and one whose own
  catalog offers a fixture id must fail naming it.

`factory/tools/seat.mjs`

- No model map of its own. `HOSTED_IDS`, `hostedModel`, `droppedIds`, `droppedAudit` and
  `catalogIds` are imported from `route.mjs`; the import is the pure map, so no CLI runs, and
  `hosted` follows route's map with no edit here.
- Every dashscope base renders from the tree's own `factory/writer-paths.json`; the ollama lines
  are gone. The qwen-code harness, its `desktop-qwen` alias and every `qwen --auth-type openai`
  line are untouched.
- `--self-test` scans the RENDERED recipes for a dropped id and for a dashscope base that is not
  the spec's, and renders every recipe again from a tree whose writer-paths.json carries a fixture
  base.

No edit to `factory/writer-paths.json`: both files read it, neither test writes it.

## Self-check, and what it changed

1. The dropped-base scan excluded `"` and backslash but not `}`, so a rendered
   `OPENAI_BASE_URL` default matched through its closing brace and every recipe reported a base
   that is not the spec's. The class is now `[^\s"'{}()<>\\]`.
2. `ID_SEPARATORS` was `[^A-Za-z0-9.]+`, which splits `qwen3-coder` into two tokens: the scan
   would have been vacuous (T79). It now keeps `_` and `-`.
3. A fixture that wrote a file nothing reads proved nothing. It became a tree whose own catalog
   offers the fixture id, which the read list is asked about.
4. The envelope says five dashscope sites. Measured now: the source carries seven, and the rendered
   recipes carry ten across the five recipe ids — qwen-code 3, desktop-qwen 3, aider 1,
   pc-dashscope 2, cloud-dashscope 1. qwen-code and desktop-qwen are one recipe under two ids, so
   the honest count is seven rendered sites over four distinct bodies. The fixture asserts `>= 5`,
   so a recipe that stops rendering a base at all is caught.

two. Not mine to edit; step 20 stays red until that call is made.
