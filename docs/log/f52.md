## What changed

`factory/tools/route.mjs`

- `droppedIds()` reads `factory/writer-paths.json` dropped.ids; nothing keeps a copy. `droppedAudit()`
  answers `empty`/`dirty`/`clean` with the count it examined; an empty list is a named failure, never
  a pass (F49).
- `familyOf()` answers `deepseek` for an id the catalog or the hosted map knows, `null` otherwise; a
  null family is refused by `resolve()` as `reason unrecognised-id`, `providerModel`/`path`/`key`/
  `base` null, non-zero exit (D-71). The "not deepseek therefore qwen" fallthrough is gone; the
  `qwen3-coder` row is out of `HOSTED_IDS`.
- C4: `tokensOf()` splits on `[^A-Za-z0-9._-]+`, so a token keeps `.` `_` `-` and a dropped id glued to
  a full stop (`qwen3-coder.` ending a sentence) was a token the scan missed. Each token is offered
  again with trailing `[._-]` trimmed; the untrimmed form stays, so a dropped id inside a live one is
  still not reported. The class was not widened; the trim is the fix.

`factory/tools/seat.mjs` (untouched in correction 1)

- No map of its own: `HOSTED_IDS`, `hostedModel`, `droppedIds`, `droppedAudit`, `catalogIds` come from
  `route.mjs`; the import runs no CLI, `hosted` follows route unedited.
- Every dashscope base renders from the tree's own `writer-paths.json`; the ollama lines are gone.
  Exactly one `qwen --auth-type openai` line went with them:
  `#   qwen --auth-type openai --model qwen3-coder`. P2 forbade that dropped id in a rendered recipe
  while the first envelope's must-stay-true required every such line to stay: one line was told both
  ways. The count goes 10 at `008a309` to 9. Nine launch lines remain, and the harness, its
  `desktop-qwen` alias, the topology id, the contract enum and the meter are intact.

`factory/tools/seatReturn.mjs` (correction 1)

- C2: `sameModel()` no longer folds strangers -- `if (String(a) === String(b)) return true; const left
  = providerId(a); return left !== null && left === providerId(b);`. An id the table does not list has
  no canonical form (D-71 refuses it with a null), so it agrees with itself by string and nothing
  else. The assertion holding this was restored, not deleted.
- C3: the pairs fixture holds live pairs only -- `deepseek-flash`/`deepseek-v4.1-flash` and
  `deepseek-v4-pro`/`deepseek-v4-pro-0813`. The `["qwen3-coder","qwen3-coder-plus"]` row was vacuous:
  D-68 drops both ids, both sides fold to `null`, all four clauses passed on `null === null` and
  proved nothing (T13). What still proves the fold is those two deepseek pairs, with the two clauses
  that must stay false kept.

No edit to `factory/writer-paths.json`.

## Self-check, and what it changed

1. The dropped-base scan excluded `"` and backslash but not `}`, so a rendered `OPENAI_BASE_URL`
   default matched through its brace and every recipe reported a base not the spec's; class now
   `[^\s"'{}()<>\\]`.
2. `ID_SEPARATORS` was `[^A-Za-z0-9.]+`, splitting `qwen3-coder` into two tokens, which would make the
   scan vacuous (T79); it keeps `_` and `-`, and C4 adds the trailing-punctuation trim.
3. A fixture that wrote a file nothing reads became a tree whose own catalog offers the fixture id;
   the envelope's five dashscope sites measure seven in the source and ten rendered over five recipe
   ids; the fixture asserts `>= 5`.
