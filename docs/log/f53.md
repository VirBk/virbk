# F53 — A check names the surfaces it scanned, and a fold is proved where it is consumed

Base `77a3471`, live main at issue; `writer/F53` already contained it, so no rebase was needed.

## What changed

`factory/tools/route.mjs`

- `droppedAudit` now returns `surfaces` — the labels of the objects it actually read — beside `examined`, the
  ids it holds. A count of ids is not a count of surfaces: a report of `examined 6 id(s)` over an empty
  surface list is a pass that cannot be told from a check that never ran (F49), so an empty surface list is
  its own status, `no-surfaces`, and it FAILS naming itself. `check-dropped` prints both counts and the
  surface labels.
- The self-test asserts the shipped surface list is non-empty before asserting it clean, so the check that
  reports "clean" cannot be a check that read nothing. The seam fixtures (lists this file writes) assert the
  surface count for the clean, dirty and empty cases, and drive the surfaceless one: status `no-surfaces`,
  `examined 1`, the line naming `0 surface(s)`. `shippedSurfaces()` never returns empty while route's map
  and the catalog have entries, so that branch is reached by the seam, not by the live tree.

`factory/tools/seat.mjs`

- The clause that compared `hostedModel(writerModel)` with `HOSTED_IDS[writerModel]` compared route against
  route: both sides read out of route.mjs, so a copy of the map re-grown inside this file would have passed
  it (T75, T48). It is now a scan of this file's OWN source (`fileURLToPath(import.meta.url)`), refusing any
  `"<native id>": "<hosted id>"` pair route owns. The hosted map stays route.mjs's alone; a local copy
  cannot agree with route by hand and drift on the next change to either.
- The pro arm of that map is driven: `hostedModel("deepseek-v4-pro")` and the aider carrier line it renders.
  Only flash and passthrough were exercised, and the live pick never selects pro, so the pro row could move
  in route.mjs with this step green (T48, D-59).

`factory/tools/seatReturn.mjs`

- A fixture drives `record()` — the fold that SHIPS — with ids the router cannot place. **The consumption is
  `record()`'s `meter.ids.find((id) => sameModel(id, row.model))`; the helper is `sameModel` and the
  `sameModel(...)` pairs pinned at the top of the self-test.** A fixture that called `sameModel` again,
  under any name, would restate the defect (T13, D-59, D-69): the meter records `zzz-unknown-a`; a return
  claiming that id must be accepted, and one claiming `zzz-unknown-b` must be refused naming both.
- `--template` (the command a returner runs, not the constant, D-59) must emit the D-72 review row with all
  three of `REVIEW_FIELDS` discoverable, while a return that omits the row still passes — the row is
  optional and an EMPTY one stays a named refusal (T84).

## Five properties, five mutations

Each mutation edits the file the named step invokes; the command is the exact one step 08, 09 or 20 runs,
from the repository root. Every one exits 1. The originals were held in memory and restored after each; a
final byte comparison reported all three files identical to their originals.

    P1  record()'s fold restored: `meter.ids.find(...)` -> `meter.ids.length ? meter.ids[0] : null`
        step 20 exit 1
          record() folded two unrecognised ids into one model
          a return whose model disagrees with the meter was recorded
    P2  a byte-identical local map re-grown in seat.mjs and used for the flash pick
        step 09 exit 1
          seat.mjs carries a local copy of route's hosted map: deepseek-flash deepseek-v4-pro
    P3  shippedSurfaces() returns []                      step 08 exit 1
          the-shipped-surface-list-is-empty-so-the-scan-proves-nothing: got false want true
          the-shipped-surface-is-clean: got no-surfaces want clean
    P4  route's pro row moved to deepseek-v4-broken-9999  step 09 exit 1
          pro-hosted: got "deepseek-v4-broken-9999" want "deepseek-v4-pro-0813"
          the pro arm never reaches a rendered recipe: ... aider --model openai/deepseek-v4-broken-9999
        measured collateral: step 08 also reds (map-native-id), because route asserts its own map.
    P5  the review row dropped from the printed template  step 20 exit 1
          the printed template carries no review row, so D-72's row is undiscoverable

P3's and P4's mutations red other clauses of the same step beside the named one, and P4 reds step 08 too;
each mutation is posted against the step it names, and the collateral is measured, not assumed.

## Self-check, and what it changed

1. Three of the four files already carried comments labelled `P1`..`P5` from earlier lanes (F50, F52, F54)
   with different properties. Mine are labelled `F53 Pn`, so a reviewer can tell whose property is whose;
   nothing else in those comments was touched.
2. The mutation harness's first run reported P2 GREEN. The clause was not at fault: the harness applied each
   replacement to a fresh copy of the original, so the second replacement silently undid the first and the
   file under test was unmutated. Composing every replacement of one mutation before writing reds it. A
   green mutation run is a claim about the harness until the mutation is proved to be in the file.
3. `docs/log/f53.md` is held under the 8 KB glob cap, and the untracked launch leftovers (`packet.txt`,
   `seat-f53.out`, `seat-f53.err`) are left untracked — the changed set is the four held paths.
