# F53 — a check names the surfaces it scanned, and a fold is proved where it ships

Base `27d14b8`, live main at issue and this branch's merge-base, so no rebase was needed. The review's
correction is folded in below, not appended as a block of its own.

## What changed

`factory/tools/route.mjs`

- `droppedAudit` returns `surfaces` — the labels of the objects it actually read — beside `examined`, the
  ids it holds. A count of ids is not a count of surfaces: `examined 6 id(s)` over an empty surface list is a
  pass that cannot be told from a check that never ran (F49), so an empty list is its own status,
  `no-surfaces`, and it FAILS naming itself. `check-dropped` prints both counts and the labels.
- (C5) A surface now counts only when it CARRIES TEXT: the first cut counted every object's label, so two of
  three surfaces could hold `""` while the report said `examined 6 id(s) over 3 surface(s)` and passed. A
  blank surface is named in the lines, and its presence makes the status `empty-surfaces`, which is not
  clean. That cut also hid a blind fixture — the CLI seam's tree named no catalog, so one of its three
  surfaces was blank and it still asserted `exit 0`; it now writes one.
- The self-test asserts the shipped surface list is non-empty before asserting it clean, so a "clean" report
  cannot be a check that read nothing. The seam fixtures assert the surface count for the clean, the dirty
  and the empty-dropped-list cases, drive the surfaceless one (`no-surfaces`, `examined 1`, the line naming
  `0 surface(s)`), and — added with C5 — blank two of three surfaces (status `empty-surfaces`, count 1, both
  blank labels named, one whitespace-only) and blank all (status `no-surfaces`, count 0, the label named).

`factory/tools/seat.mjs`

- (C1) The clause P2 deleted is back, BESIDE the scan it was swapped for:
  `want("hosted-is-not-route-s-map-for-the-live-pick", hosted, HOSTED_IDS[writerModel] || writerModel)`
  compares the value the live pick was bound to with route's map read a second time, and reds the moment a
  local map this file grew and pointed the pick at diverges — P2's harm, which a source scan cannot see,
  because a diverging value is not a pair route's map holds. The scan reds the copy that still agrees by
  hand. Neither check contains the other.
- The scan reads this file's OWN source (`fileURLToPath(import.meta.url)`) and refuses any
  `"<native id>": "<hosted id>"` pair route owns. (C3) It names its LIMIT in the code, the way T77 names the
  one it leaves uncovered: one spelling — double-quoted key, bare colon, double-quoted value, one line.
  Single quotes, `Object.fromEntries([[k, v]])` and a computed `[K]: v` are spellings it does not see, and no
  source scan closes that race. The ids are escaped before they become a pattern, so the dot in
  `deepseek-v4.1-flash` is a literal, not a wildcard.
- (C2) A positive control drives the matcher against a source that CONTAINS the pair, built from route's map
  at run time — a literal pair typed here would be the local copy the scan rightly refuses — and asserts it
  fires: without it a clean scan and a matcher that never ran are the same observation (F48). The pro arm is
  driven too: `hostedModel("deepseek-v4-pro")` and the aider carrier line it renders (T48, D-59).

`factory/tools/seatReturn.mjs`

- A fixture drives `record()` — the fold that SHIPS — with ids the router cannot place; the consumption is
  `record()`'s `meter.ids.find((id) => sameModel(id, row.model))`. A fixture that called `sameModel` again
  would restate the defect (T13, D-59, D-69): the meter records `zzz-unknown-a`; a return claiming that id is
  accepted, and one claiming `zzz-unknown-b` refused naming both. `--template` must emit the D-72 review row
  with all three of `REVIEW_FIELDS` discoverable, while a return that omits it still passes (T84).

## Self-check, and what it changed

1. The harness's first run reported P2 green. The clause was not at fault: the harness applied each
   replacement to a fresh copy of the original, so the second undid the first and the file under test was
   unmutated. A green mutation run is a claim about the harness until the mutation is proved to be in the
   file. (Earlier lanes' `P1`..`P5` comments are relabelled `F53 Pn`; nothing else in them was touched.)
2. Read the difference for sentences it does not support. Three were in this log and are corrected here: that
   a local copy cannot agree with route by hand (C1's byte-identical mutation is such a copy, and it agrees);
   that the seam fixtures assert a surface count for an empty surface list (no fixture blanked a surface —
   that gap was C5); and P1's mutation, named above.
3. Drove the CLI the gate runs (`check-dropped`) over a fixture tree, because a helper that is right
   in-process can still be wired wrong. That is what found the tree that names no catalog.
4. `git status`: this correction changes `factory/tools/route.mjs`, `factory/tools/seat.mjs` and this log.
   `seatReturn.mjs` carries no change from it — the harness wrote it transiently for P1 and restored it
   byte-identical (58,997 bytes) — and the untracked paths are the launch leftovers `packet.txt`,
   `seat-f53-c1.out`, `seat-f53-c1.err`.
