What you cannot see from the file
  Steps run as spawnSync("bash", ["-e", scriptPath], { cwd: workDir }), and both paths are Windows paths. On this machine bash sometimes resolves to the WSL launcher, which cannot read a Windows path as a file and cannot take a Windows cwd, so EVERY step exits non-zero at ANY commit — including a commit that is green from git-bash a second later.
  Two seats paid for this last sitting, each spending calls to prove the red was not its own. The gate prints step NAMES and writes stderr to a log file, so from inside a print-mode seat the cause is invisible. That is S24. Rewriting T70, whose sentence about shell dialect this makes false, is the control plane's act at landing.

The rule to implement
  Before the first step runs, write a probe script and run it THE WAY A STEP IS RUN: a file in logDir, spawned as bash -e, cwd set to workDir. The form is the whole point: a probe shaped like bash -c true SUCCEEDS under the WSL launcher and leaves the 21 reds where they are.
  If the probe does not exit 0 — not spawned at all, or spawned and failed — print one diagnostic, run NO steps, print no step lines, and exit with a status that is not the status of a failed gate.

Acceptance
  Six properties. Each gets its own fixture and its own mutation, and each mutation must red for its property ALONE. If one mutation reds two properties, one of them is untested and the item is not done. Paste what every mutation printed, naming the property it reds for.
  1 A shell that CAN run the steps changes nothing: all 21 run, a green commit still prints GATE PASSED. Mutate the probe to report unrunnable always and show this one reds — the ordinary case needs a fixture that could fail.
  2 A shell that cannot be spawned at all — a command name that does not exist — gives the diagnostic, no step lines, non-zero exit.
  3 A shell that CAN be spawned but fails the probe script gives the same diagnostic. This is the WSL shape and the member most likely to escape: a check written against the spawn error alone passes property 2 and leaves this one open.
  4 The diagnostic NAMES the shell it tried and carries what the probe wrote to stderr. S24 exists because a seat could not see the cause; "shell failed" does not close it.
  5 The probe uses the step's own spawn form. Mutate the probe to bash -c true and show that under the property-3 fixture the probe then passes and the 21 reds come back.
  6 The unrunnable exit status is distinguishable from GATE FAILED, so a caller and a seat can tell "this shell cannot run the gate" from "your commit is bad".
